## 目的
Phase1(ヒアリング設計)で作成したインタビューガイドと併用し、ホテル担当者に「触ってもらいながら」フィードバックを得るためのプロトタイプ。Phase3の要件定義(特に画面設計・AIガードレール)を、実際に操作できる形に落とし込んでいる。バックエンド・実データ・実AIは一切接続しておらず、すべてダミーデータ・モック挙動。

## 構成(2画面)

### 1. Main(コンシェルジュ画面)
Phase3の画面設計のうち、ホテル側が使う主要フローを1つの連続した操作として体験できる:

`ホーム → クイック相談(要望入力) → AIによる追加質問 → 候補一覧 → 候補比較(詳細) → ゲスト向け提案文(日英切替・編集可) → 有人デスクへのエスカレーション → 相談履歴`

**デモ用に強調している設計判断(Phase0決定2)**:
- ヘッダーの「コンシェルジュ本人 / Dexterスタッフ代行」切替ボタンで、同じ画面・同じ操作が**誰の入力か**によって変わることを可視化。「Dexterスタッフ代行」を選ぶと、画面上部に代行入力中であることを示すバナーが表示される。
- 候補一覧・体験詳細では、Phase0の信頼性原則(情報源・最終確認日・信頼度区分・要確認事項の必須表示)をそのまま実装。料金・予約方法・キャンセル条件・対応言語など、ホテル提案書に記載のない項目はすべて「要事業者確認」と表示し、架空の数値を作っていない。
- AIによる追加質問画面で、回答が増えるほど「AIの確信度」表示が変わる(低い/中/高い)ことで、情報不足時に断定しないという設計原則を体感できるようにしている。

**使用している体験データ**: ホテル提案書(PPTX)記載のサンプル3件(豊洲・築地マグロ体験、新宿盆踊り体験、忍者道場体験)。料金・所要時間・予約条件等、原資料に記載のない情報は創作せず「要事業者確認」としている(本タスクの方針20に準拠)。

### 2. DeskQueue(Dexter運用管理画面)
Phase3画面設計の「デクスター運用管理画面」に相当。ホテル側のエスカレーションがDexterスタッフ側でどう見えるかを示す簡易キュー画面。SLA表示、対応中/回答済みへのステータス変更(モック)が可能。ホテル向けヒアリングでは必須ではないが、デクスター社内での「デスクモードの実感」共有、および投資家・社内説明用に有用。

## 技術的な位置づけ
この段階はまだ「クリック可能なプロトタイプ」であり、Phase6で作る実際のMVP(認証・マルチテナントDB・RAG・LLM連携等を備えたシステム)とは別物。表示・遷移・ダミーAI応答のみを実装しており、データはすべてブラウザ内の一時的な状態(ページを閉じると消える)。

## 既知の制約・今後の対応
- 実際のAI(RAG検索・生成)は接続していない。候補一覧・提案文はあらかじめ用意した固定内容。
- 多言語は日本語・英語のみ(Phase3の非機能要件と同じ、MVPスコープ)。
- 個人情報入力の警告文は表示しているが、実際の入力検知・ブロック機能は未実装(視覚的な注意喚起のみ)。
- モバイル表示の最適化は未検証(Phase3非機能要件ではPC・タブレット優先としており、本プロトタイプもPC幅を前提に設計)。

## 次のステップ(Phase5への申し送り)
