# KPI設計

Phase2のマーケティング・営業KPIと重複しない範囲で、プロダクト運用・顧客価値の観点からKPIを整理する。「ホテル側から取得困難な指標」と「現実的に取得できる代替指標」を区別する。

## 経営KPI
| 指標 | 取得可否 | 備考 |
|---|---|---|
| 契約ホテル数 | 取得可能 | 事業計画書の3カ年計画と直接連動 |
| 月次経常収益(MRR) | 取得可能 | プラン別・モード別(デスク/セルフサービス利用比率)の内訳も取得 |
| 解約率(チャーン) | 取得可能 | |
| 契約単価 | 取得可能 | Entry/Standard/Premium別 |

## 営業KPI
Phase2 `06_sales_strategy.md`のパイプラインKPIを参照(リード数、面談化率、PoC移行率等)。

## プロダクトKPI
| 指標 | 取得可否 | 備考 |
|---|---|---|
| 週次・月次アクティブ率(ホテル単位・利用者単位) | 取得可能 | システムログから直接取得 |
| 1ホテル当たりの利用件数(相談案件数) | 取得可能 | デスクモード/セルフサービスモード別に分解 |
| 検索から提案完成までの時間 | 取得可能 | システムログから直接取得 |
| 有人エスカレーション率 | 取得可能 | セルフサービスモードの完成度の指標 |
| 情報誤り報告率 | 取得可能 | 誤情報報告機能のログから |
| 修正率(報告後の実際の修正対応率) | 取得可能 | |
| コンテンツ1件当たりの維持費 | **取得困難** | Dexter運用者の工数按分が必要で、システムログだけでは出ない。**代替指標**: Dexter運用者の体験情報登録・更新にかかった作業時間の自己申告集計(簡易的な工数記録) |

## 顧客価値KPI
| 指標 | 取得可否 | 備考 |
|---|---|---|
| 従来業務からの時間削減 | **取得困難(直接計測は不可)** | ホテル側の「導入前の対応時間」は主観申告に頼るしかない。**代替指標**: PoC開始前にヒアリングで基準値(自己申告)を取得し、導入後にシステムログの実測時間と比較する(Phase1回答記録シートの⑥と連動) |
| 候補採用率 | 取得可能 | 提案の採用状況フィールド(データモデル)から |
| ゲストへの提案実施率 | **取得困難** | 実際にゲストに提示したかはシステム外の行動のため、コンシェルジュの入力(フィードバック機能)に依存する。**代替指標**: フィードバック登録率そのものを完全性の代理指標として併用 |
| 予約・体験実施率 | **取得困難** | 予約機能を持たないMVP設計のため、直接計測不可。**代替指標**: フィードバック登録時の「実施有無」自己申告項目 |
| スタッフの回答満足度 | **取得困難(システムログでは不可)** | **代替指標**: 定期アンケート(四半期ごと等)をPhase7以降で設計 |
| ゲストの満足度 | **取得困難** | Dexterはゲストと直接接点を持たない。**代替指標**: ホテル側のレビュースコア・NPSの変化(ただし他要因との因果分離は困難である旨を明記して扱う) |
| 継続利用意向 | **取得困難(システムログでは不可)** | **代替指標**: 契約更新率そのもの、または更新前アンケート |
| 有料契約転換率 | 取得可能 | 無償キャンペーンからの移行データ(Phase0決定1と連動) |

## PoCにおける基準値取得方法
- 導入前基準値: Phase1ヒアリングの⑥(1件あたり対応時間)、②(相談頻度)の自己申告値を基準値として記録
- 導入後数値: システムログの実測値(検索から提案完成までの時間、相談件数)と、定期的な自己申告アンケートを併用して比較する
- 比較時は「システムログによる客観値」と「自己申告による主観値」を区別して報告し、両者が乖離する場合はその要因を分析する

## 未決定事項
- 具体的な目標値(例: エスカレーション率を何%以下に抑えるか)は、PoC実施前のベースラインデータがないため、Phase7(テストとPoC準備)で初期目標を仮設定し、PoC結果を踏まえて見直す。
