# データモデル(概念設計)

実装(テーブル定義・DDL)はPhase6で行う。ここではエンティティと主要属性、関連を定義する。Phase0決定2(デスク/セルフサービス2モード)、決定1(有料プラン+無償キャンペーン)を反映している。

## エンティティ一覧と主要属性

### ホテル(Hotel)
id、名称、分類(ラグジュアリー/シティ/リゾート/旅館/ブティック等)、所在地、外国人ゲスト比率(参考値)、チェーンID(所属チェーンがある場合)、契約プランID、契約状態(無償キャンペーン中/有償/解約)、キャンペーン終了日

### チェーン(Chain)
id、名称、本部連絡先、所属ホテル一覧

### 契約プラン(ContractPlan)
id、ホテルID、プラン種別(Entry/Standard/Premium)、デスクモード月間上限件数、セルフサービスモード利用可否、月額料金、契約開始日、無償キャンペーンフラグ、キャンペーン終了予定日、終了時移行方式(自動移行/個別商談/自然終了)

### 利用者(User)
id、ホテルID(null可、Dexterスタッフの場合)、氏名、役割(下記「権限」参照)、言語設定、在籍状態

### 権限(Role)
ホテル一般利用者(コンシェルジュ)、ホテル管理者、Dexter運用者(デスクスタッフ)、Dexterシステム管理者 の4区分(詳細は`04_permissions.md`)

### ゲスト要望(GuestRequest)
id、相談案件ID、テーマ、エリア希望、人数、日程、予算感、対象ゲスト属性(年齢層・食事制限・身体的制約等、個人を特定しない範囲で)、自由記述

### 相談案件(Inquiry)
id、ホテルID、起票者(利用者ID)、**入力者ロール(Dexterスタッフ代行 / ホテルコンシェルジュ本人)**、ステータス(AI回答中/デスクエスカレーション中/回答済み/クローズ)、緊急度(当日/翌日/後日)、起票日時、回答日時、関連する提案一覧

### 提案(Proposal)
id、相談案件ID、体験ID(複数可)、推奨理由、不適合理由・注意事項、生成された提案文(日本語)、生成された提案文(英語等)、生成日時、採用状況(採用/不採用/ゲスト未提示)

### 体験(Experience)
id、名称、概要、地域ID、テーマID、対象ゲストID、対応言語、料金帯、所要時間、季節、アクセス情報、予約方法、キャンセル条件、リスク・注意事項、情報源ID、最終確認日、確認者、信頼度区分(デクスター確認済み/提携先確認済み/公開情報のみ)、公開ステータス(下書き/承認済み/非公開)、有効期限

### 体験事業者(ExperienceProvider)
id、名称、連絡先、対応可能な体験一覧、契約・提携状態

### 地域(Region)
id、名称(都道府県・市区町村等)、DMO/観光協会連携情報

### テーマ(Theme)
id、名称(自然/食/工芸/文化等)

### 対象ゲスト属性(GuestSegmentTag)
id、名称(富裕層/ファミリー/文化関心層/長期滞在者等)

### 情報源(Source)
id、種別(現地取材/事業者提供/公開情報)、URL等参照先、取得日

### ホテル別推奨設定(HotelRecommendationPolicy)
id、ホテルID、推奨方針(自由記述+タグ)、紹介禁止事項(NGリスト)

### フィードバック(Feedback)
id、提案ID、登録者、内容、ゲスト反応(良好/普通/不良等)、登録日時、共通知見化ステータス(未反映/匿名化済み/反映済み)

### 有人相談(DeskEscalation)
id、相談案件ID、エスカレーション理由、担当Dexterスタッフ、対応履歴、回答日時、SLA遵守状況

### AI出力(AIOutput)
id、相談案件ID、モデル/バージョン、入力プロンプト概要、出力内容、信頼度スコア、参照した情報源一覧、生成日時

### 監査ログ(AuditLog)
id、操作者、操作種別、対象エンティティ、操作日時、変更前後の差分概要

## 主要な関連
- ホテル 1—N 利用者
- ホテル 1—N 相談案件
- 相談案件 1—1 ゲスト要望
- 相談案件 1—N 提案
- 提案 N—N 体験
- 体験 N—1 地域、体験 N—1 情報源、体験 N—N テーマ、体験 N—N 対象ゲスト属性
- 相談案件 1—0..1 有人相談(エスカレーションされた場合のみ)
- 提案 1—0..N フィードバック
- ホテル 1—0..1 ホテル別推奨設定
- 全エンティティの変更操作 → 監査ログ(N)

## テナント分離の原則
- ホテルID・利用者IDに紐づくデータ(相談案件・ゲスト要望・提案・フィードバック・ホテル別推奨設定)は、原則として当該ホテルの利用者・Dexter運用者以外からアクセスできない設計とする。
- 体験・体験事業者・地域・テーマ等の「共通知見」は全ホテルで共有するが、個別ホテルの相談履歴・フィードバックの原文は共有しない。フィードバックが共通知見に反映される際は匿名化・Dexterによる承認を経る(`01_feature_list.md`のAI・RAG機能「利用者の修正内容を改善候補として蓄積」と対応)。
