# 権限設計

## ロール定義

| ロール | 所属 | 主な操作 |
|---|---|---|
| ホテル一般利用者(コンシェルジュ) | ホテル | 相談案件の作成・閲覧(自ホテル分のみ)、提案の閲覧・編集、フィードバック登録、有人相談への引き継ぎ依頼 |
| ホテル管理者 | ホテル | 上記に加え、自ホテルの推奨方針・NGリスト設定、ユーザー管理(自ホテル内)、利用状況分析の閲覧、誤情報報告 |
| Dexter運用者(デスクスタッフ) | Dexter | 担当ホテルの相談案件へのデスクモード代行入力、体験情報の登録・編集(下書き)、有人相談キューの対応 |
| Dexterシステム管理者 | Dexter | 体験情報の公開承認、全ホテル横断の監査ログ閲覧、ユーザー・権限管理全体、契約プラン設定、テナント分離設定 |

## アクセス制御マトリクス(抜粋)

| データ/機能 | ホテル一般利用者 | ホテル管理者 | Dexter運用者 | Dexterシステム管理者 |
|---|---|---|---|---|
| 自ホテルの相談案件 | 閲覧・作成 | 閲覧・作成・削除 | 担当分のみ閲覧・代行入力 | 全ホテル閲覧可(監査目的) |
| 他ホテルの相談案件 | 不可 | 不可 | 担当外は不可 | 監査ログ経由でのみ参照可(要理由記録) |
| ホテル別推奨設定 | 閲覧のみ | 編集可 | 閲覧のみ(提案作成の参考) | 編集可 |
| 体験情報(下書き) | 不可 | 不可 | 作成・編集可 | 承認・差し戻し可 |
| 体験情報(公開済み) | 閲覧のみ | 閲覧のみ | 閲覧・編集提案可 | 編集・非公開化可 |
| 監査ログ | 不可 | 自ホテル分のみ閲覧可(要検討) | 不可 | 全件閲覧可 |
| 契約プラン設定 | 不可 | 閲覧のみ | 不可 | 編集可 |
| ユーザー管理 | 不可 | 自ホテル内のみ | 不可 | 全体 |

## 設計上の注意
- 「入力者ロール」(Dexterスタッフ代行/ホテルコンシェルジュ本人)は権限そのものではなく相談案件データの属性だが、Dexter運用者が代行入力する際は、あたかもホテル利用者本人が入力したかのように見せない(誰が入力したか常に記録・表示する)ことを原則とする。これは信頼性・透明性の設計原則(Phase0)とも整合する。
- ホテル管理者が監査ログを閲覧できる範囲(自ホテル分のみか、全く不可か)は、セキュリティ要件の詳細設計(Phase3継続、または法務確認後)で確定する。
